## Задание 2

    Проведите атаку на подбор пароля для службы SSH:

    hydra -L users.txt -P pass.txt < ip-адрес > ssh

    Настройка hydra:
    создайте два файла: users.txt и pass.txt;
    в каждой строчке первого файла должны быть имена пользователей, второго — пароли. В нашем случае это могут быть случайные строки, но ради эксперимента можете добавить имя и пароль существующего пользователя.
    Дополнительная информация по hydra: https://kali.tools/?p=1847.

    Включение защиты SSH для Fail2Ban:
    открыть файл /etc/fail2ban/jail.conf,
    найти секцию ssh,
    установить enabled в true.
    Дополнительная информация по Fail2Ban:https://putty.org.ru/articles/fail2ban-ssh.html.

    В качестве ответа пришлите события, которые попали в логи Suricata и Fail2Ban, прокомментируйте результат.

> Для проверки защиты SSH была выполнена атака перебора паролей с помощью Hydra. Во время атаки были зафиксированы события как в Suricata, так и в Fail2Ban.Suricata обнаружила подозрительную активность, связанную с большим количеством SSH-подключений. В журнале fast.log были зарегистрированы предупреждения:

> 08/18/2026-12:48:00 [**] [1:2210055:3] SURICATA SSH invalid banner [**]
> 08/18/2026-12:48:00 [**] [1:2210025:2] SURICATA Applayer Detect protocol only one direction [**]
> 08/18/2026-12:48:02 [**] [1:2210045:2] SURICATA STREAM excessive retransmissions [**]

> Эти события говорят о том, что IDS обнаружила аномальное поведение SSH-трафика и большое количество соединений, характерное для перебора паролей.После включения защиты SSH в Fail2Ban сервис начал отслеживать неудачные попытки входа. В журнале fail2ban.log сначала появились многочисленные записи об обнаружении подозрительных попыток подключения:

> 2026-08-18 12:48:00,637 INFO  [sshd] Found 192.168.209.20
> 2026-08-18 12:48:00,638 INFO  [sshd] Found 192.168.209.20
> 2026-08-18 12:48:00,639 INFO  [sshd] Found 192.168.209.20

> После превышения допустимого количества неудачных попыток Fail2Ban автоматически заблокировал IP-адрес атакующей машины:

> 2026-08-18 12:48:01,142 NOTICE [sshd] Ban 192.168.209.20

> Вывод: Suricata выполнила роль системы обнаружения вторжения (IDS) и зафиксировала признаки атаки на SSH, а Fail2Ban выполнил роль активной защиты — обнаружил многочисленные неудачные попытки входа и автоматически заблокировал IP-адрес атакующего (192.168.209.20). Совместная работа этих инструментов позволяет не только обнаружить атаку, но и предотвратить дальнейшие попытки подбора пароля.
